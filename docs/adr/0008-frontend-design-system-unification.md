# ADR-0008: 前端设计系统统一（视觉风格与字体）

## Status

Accepted

## Context

前端约 35 个 Vue 组件在字体、颜色、圆角的使用上不一致：部分组件硬编码字体栈（如 `ProjectNoteEditor.vue` 用系统栈、`TestExecutionView.vue` 用 SF Pro 栈、多个组件写死 mono 字体），绕过了 [index.css](frontend/src/index.css) 中已有的设计 token。目标是统一全部页面与组件的视觉风格与字体。

经评审（grilling 访谈），用户从三套方案（A 精修延续 / B 现代轻量 / C 数据紧凑）中选定 **A + 局部吸收**，即：以方案 A 为主体，吸收 B 的投影分层与 C 的紧凑表格行高。

## Decision

### 视觉方向

- 延续现有蓝色 SaaS 风，做体系化精修，不改变产品气质
- **配色**：主色蓝（light `#2563EB` / dark `#3B82F6`）不变；**橙色收敛**为「高风险操作 + 警告 + P0/P1 优先级」专用，常规按钮回归中性色
- **圆角**：从 7/10/14 微调为 **8/12/16**（sm/md/lg）
- **主题**：保留明暗双主题，暗色随方案同步调优

### 字体

- **保留** Space Grotesk（标题）+ DM Sans（正文）+ JetBrains Mono（代码），全部为 OFL 开源协议，无版权风险
- **中文走系统字体栈**（PingFang SC / 微软雅黑 / Noto Sans SC），不引入中文字体文件（避免数 MB 体积与加载负担）
- 字体固化为 token（`--font-heading` / `--font` / `--font-mono`），清除组件内全部硬编码字体栈
- 在 `frontend/public/fonts/` 补齐 OFL 许可证文件（OFL 协议的合规义务）

### 形态（A + 局部吸收）

- 卡片：1px 边框 + 轻阴影（方案 A 延续）
- 吸收方案 B：阴影分级（shadow token 体系化）
- 吸收方案 C：表格使用紧凑行高
- 侧栏保留玻璃拟态（blur）

### 工程范围

Token 重构 + **基础组件规范化**：按钮 / 输入框 / 弹窗 / 表格 / 标签（Tag）/ 弹层等抽象为统一规范组件，全站替换使用。

## Considered Options

- **方案 B 现代轻量**（无边框+投影、去玻璃拟态、宽松密度）：与现有产品气质偏差较大，未整体采用，仅吸收其投影分层
- **方案 C 数据紧凑**（扁平、紧凑密度）：工程感最强但偏冷，未整体采用，仅吸收其紧凑表格行高
- **字体改 Inter 全包中性路线**：用户认可现字体组合，未换
- **主色改 Teal 对齐 favicon**（`#0EA5A5`）：改动过大，未选；favicon 后续统一为蓝色系以消除品牌不一致
- **圆角**：7/10/14（现状）与 4/6/8（锐利）均否决，选 8/12/16 微调

## Consequences

- **Positive**：视觉统一，token 单一来源，后续维护与新增页面成本降低
- **Positive**：基础组件规范化后，样式一致性有结构性保障（而非依赖开发者自觉）
- **Positive**：字体零新增依赖、零版权风险
- **Negative**：35+ 组件需要逐一替换为规范组件，改动量大，需分批提交验证
- **Negative**：不引入中文字体，跨平台中文渲染细节略有差异（可接受的取舍）
