# ADR-0009: 文件访问权限控制（自建签名 URL，不引入 MinIO）

## Status

Accepted

## Context

平台当前所有用户文件（头像、缺陷附件、缺陷内嵌图、临时粘贴图）直接存储在服务器本地磁盘
（`PROJECTS_DATA_DIR`，默认 `data/projects/`），并通过以下方式对外提供访问：

| 数据类型 | 存储位置 | 访问方式 | 当前鉴权 |
|---------|---------|---------|---------|
| 用户头像 | `static/avatars/{uid}/{file}` | `/api/static/` 静态挂载（`StaticFiles`） | 无 |
| 缺陷附件 | `defects/temp/` → `defects/{id}/` | `GET /defects/attachments/{id}/download` | 无 |
| 缺陷内嵌图 | `defects/{id}/images/{file}` | `GET /defects/{id}/images/{file}` | 无 |
| 临时粘贴图 | `defects/temp/{file}` | `GET /defects/attachments/temp/{file}` | 无 |

**风险**：上述文件访问端点全部无鉴权，任何人拿到 URL 即可访问，未做到按项目隔离。

评估过引入 MinIO 对象存储的方案，结论是**不引入**：

- MinIO 提供的是桶/前缀级粗粒度策略（bucket policy、预签名 URL），无法直接表达
  "登录用户是否是某缺陷所属项目的成员"这类细粒度权限——细粒度必须由应用层实现。
- 当前无多机共享、水平扩容、生命周期管理、图片处理等远期需求（数据总量小，
  大头是运行时虚拟环境，而 venv/source 依赖 POSIX 文件语义，本就不应放入对象存储）。
- 引入 MinIO 会新增基础设施组件（部署、运维、S3 客户端），为不需要的能力买单。

## Decision

**保持本地磁盘存储，在应用层增加鉴权 + 自建 HMAC 签名 URL**，实现按项目隔离的文件访问控制。

### 权限规则

| 文件类型 | 访问规则 |
|---------|---------|
| 用户头像 | 保持公开（`/api/static/` 不变）。成员列表、用户搜索需渲染他人头像，隔离成本高且无必要 |
| 缺陷附件 / 内嵌图 | **项目成员限定**：校验链路 附件/内嵌图 → 缺陷（`defect_id`）→ `project_id` → `project_members` 表，仅项目成员可访问 |
| 临时粘贴图 | **仅上传者可见**：上传接口记录归属（`user_id`），下载时校验当前用户为上传者 |

### 签名 URL 机制

- **密钥**：独立 `FILE_SIGN_SECRET` 配置项（`.env`），与 `JWT_SECRET` 隔离，避免互相泄露。
- **算法**：HMAC（sha256），签名内容为 `文件标识 + 过期时间`，密钥为 `FILE_SIGN_SECRET`。
- **有效期**：5-10 分钟，过期后刷新页面重新签发。
- **签发**：后端在返回缺陷详情/附件列表时动态将文件 URL 替换为签名 URL
  （复用 `_finalize_steps_images` 的 URL 替换位置模式），**前端 `<img>` 直链零改动**。
  注：`<img>` 标签无法附带 `Authorization` header，故不能用 Bearer 方案，必须走签名 URL。
- **校验**：文件下载端点在返回文件前验证签名有效 + 权限规则通过。

### 实施改动点（范围：仅缺陷模块）

1. **签名服务**：签发/验证一对函数（`backend/app/services/` 或 `utils/`），密钥来自 `FILE_SIGN_SECRET`。
2. **附件下载** `GET /defects/attachments/{id}/download`：鉴权，校验当前用户为附件所属缺陷项目的成员。
3. **内嵌图** `GET /defects/{id}/images/{file}`：改为签名 URL 访问，校验项目成员。
4. **缺陷详情/列表返回**：动态替换 steps HTML 中图片 URL 为签名 URL。
5. **临时图** `GET /attachments/temp/{file}`：仅上传者可见（上传时记录 `user_id`，或 temp 按用户分子目录 + 签名）。
6. **清理（可后置）**：定期清理 `defects/temp/` 中未落库的孤儿文件。

### 明确不做（本次）

- 不引入 MinIO / 对象存储。
- 不迁移现有文件（保持本地磁盘布局）。
- 头像保持公开，不做登录门控。
- 不覆盖测试项目源码下载、报告等非缺陷模块文件。

## Consequences

- **正向**：缺陷相关文件实现按项目隔离；`<img>` 直链无需前端改造；无新基础设施依赖；
  未来若出现多机/容量需求，存储层（本地磁盘路径抽象）可平滑替换为 MinIO，签名机制不变。
- **代价**：下载/内嵌图访问增加签名校验与成员关系查询开销；签名 5-10 分钟过期，
  长期停留页面需刷新重新签发；临时图归属需要额外记录。
- **注意**：历史中已存储的缺陷文件路径不变（仅访问链路加签名），存量数据无需迁移。
