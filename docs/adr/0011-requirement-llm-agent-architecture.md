# ADR-0011: 需求管理智能体架构（后端代理 + 双模型 + 生成时附带评分）

## Status

Accepted

## Context

新增「需求管理」模块：上传需求文档（飞书链接 / 离线文件）后，由智能体（在线 LLM API）分步完成需求评审、拆解 Story、生成测试用例，每步固定 JSON 格式输出、支持评论重新评审、用户确认后进入下一步。

系统已有 `TitleGenerator`（`backend/app/services/title_generator.py`）通过环境变量直连 OpenAI 兼容 API 生成用例标题。需求智能体调用频率更高、成本更大、且需要多模态（识别截图），不能照搬「环境变量 + 前端直连」的模式。

## Decision

### 后端代理 + 全局配置存储

- LLM 配置存**后端数据库**（全局一份：provider / api_base / 文本模型 / 视觉模型 / API key），登录用户可改，前端「设置」弹窗切换
- 所有智能体调用**由后端代理**（`httpx`），API key 不进入前端代码
- 配置模型：`LLMSettings`，字段含 `text_model`（评审/Story/用例）与 `vision_model`（截图/图片识别，可为空则视觉功能降级为仅存档）
- 复用现有 OpenAI 兼容 `chat/completions` 协议；`provider=ollama` 时免鉴权（沿用 TitleGenerator 约定）

### 三步流程 + 状态机

```
待评审 → 评审通过 → Story确认 → 用例生成 → 完成
   ↑______ 任一步可「重新评审」：携带人工评论重调当前步智能体，直接覆盖输出
```

- 每步输出**固定 JSON 结构**（评审：结论/风险/问题清单；Story：标题/描述/验收标准；用例：标题/前置/步骤/预期），前端渲染为可编辑卡片
- 手动按钮触发每一步调用（成本可控）；用例全量批量生成、单个可单独重生成
- 需求标题/摘要/优先级由智能体生成，用户可编辑

### AI 评分

- 每次生成/重生成输出时，**同一次调用**附带返回环节整体评分（100 分制）+ 评分原因，不额外消耗一次调用
- 评分 < 60 时该环节输出标记为「建议重新评审」状态标识，不自动触发
- 评分与原因随环节输出一起存储（环节表内嵌 `score` / `score_reason` 字段）

## Considered Options

- **前端直连 LLM**：key 暴露在浏览器、无法集中管控成本，未选
- **环境变量静态配置**：无法运行时切换、无法存视觉模型，未选
- **独立评分调用**：每环节多一次调用、成本翻倍，未选（改为同次调用附带评分）

## Consequences

- **Positive**：key 只存后端，可审计、可统一限流
- **Positive**：前端可运行时切换模型，用户体验好
- **Positive**：评分不额外计费，低分提示引导用户重新评审
- **Negative**：后端新增 `LLMSettings` 表与代理接口，需同步考虑 key 的明文存储与访问控制（仅登录用户可读写）
- **Negative**：视觉模型缺失时截图分析降级，需在前端提示
